    AI·검색엔진용 사이트 구조¶

    민성 한의학 아카이브는 개별 문서를 나열하는 방식보다 환자의 자연어 질문에서 출발해 전문 한의학 지식과 현대 임상근거까지 이어지는 계층형·관계형 구조를 사용합니다.

    핵심 탐색 흐름¶

    자연어 질문 → 증상·질환 → 위험신호·감별 → 한의학적 변증 → 본초·방제·침구치료 → 현대 임상근거 → PMID·DOI

    모든 문서를 이 순서대로 읽을 필요는 없습니다. 증상·처방·경혈·연구 중 알고 있는 정보에서 시작해 관련 문서로 이동합니다. R-code 등 분류 코드는 필요한 문서의 보조 정보이며, 코드나 내부 링크의 연결만으로 진단·처방의 적합성을 확정하지 않습니다.

    질문에 따라 시작점을 고릅니다¶

    지금 찾는 것 먼저 읽을 자료 이어서 확인할 내용
    증상은 알지만 진단명은 모름 증상으로 찾기 관련 질환·감별·위험신호
    특정 질환의 치료 연구 질환별 근거 안내 질환 본문의 연구 절 또는 고유한 근거 자료에서 대상·중재·비교군·결과 확인
    같은 이름의 처방이 서로 다른 이유 처방 출전·구성 수록본·약량·제형·가감과 비교 문서
    비슷한 약재·처방의 차이 본초 비교 · 처방 비교 약용 부위·배합·출전·약량과 유사 처방의 감별
    고전의 한 구절과 해석 고전 원문·해석 서명·편목·조문·판본과 전후 문맥
    사람과 사건으로 고전을 읽기 민성의담 왕실 진료·돌봄·본초와 처방 이야기에서 실제 기록과 관련 문서 확인
    매일 읽고 복습하기 오늘의 한의학 · 학습실 날짜별 카드·생활 실천·원문 풀이와 과목별 복습
    한 문서를 도구에서 읽기 페이지 색인 대표 주소와 페이지별 JSON

    예를 들어 ‘허리가 아플 때 침 연구’를 찾으면 요통 문서에서 증상의 범위를 확인하고, 같은 문서의 요통 연구 절에서 해당 연구의 대상과 치료 조건을 읽습니다. 질환 설명과 연구 절을 함께 읽고, 탐색 링크의 연결과 개별 연구의 결론은 구분해 정리합니다.

    1. 환자 언어와 증상¶

    • 증상으로 찾기
    • 증상·질환
    • 증상 기반 한약 탐색
    • 질문형 답변 가이드

    질환명을 모르는 사용자도 “속이 더부룩해요”, “잠이 안 와요”, “허리가 오래 아파요”, “기침이 계속돼요” 같은 표현에서 시작하도록 설계합니다. 증상 안내에서 진료 분야별 핵심 허브와 대표 질환 본문으로 이어지며, 통합된 짧은 안내의 기존 주소는 해당 본문이나 관련 절로 연결합니다. 예를 들어 무릎의 동작별 통증은 무릎통증에서 평가·치료·경과와 함께 읽습니다.

    2. 질환과 현대 임상근거¶

    • 연구·근거 통합 안내
    • 출처·근거 카드 허브
    • 질환별 현대 근거 카드
    • 근거 가이드
    • 참고문헌 데이터베이스

    질환의 평가·변증·치료와 해당 임상근거를 함께 읽는 구조를 우선합니다. 같은 질환을 반복 설명하던 확장·근거 카드는 기존 질환 본문의 연구 절로 통합하고, 기존 주소와 유입 링크는 대표 문서·해당 절로 이어지도록 유지합니다. 고유한 연구 질문을 다루는 자료와 여러 질환을 잇는 근거 허브는 관련 본문으로 연결합니다.

    질문 현재 대표 경로
    허리·목·어깨·무릎 통증의 평가와 치료 연구 요통 연구 · 목통증 · 어깨통증 연구 · 무릎통증 연구
    잠들기 어렵거나 식후 더부룩할 때의 치료 연구 불면 연구 · 기능성소화불량 연구
    국내 한의치료·일본 Kampo·국제 지침을 함께 찾기 연구·근거 통합 안내 → 실제 대상·제제·치료·비교군·기간·결과·원 논문

    연구를 인용할 때는 현재 도착한 대표 문서의 해당 절을 확인합니다. CPG·체계적 문헌고찰·무작위시험·관찰연구·기전연구는 서로 다른 질문에 답하는 자료이며, 원방·가감방·시험제제의 차이도 함께 표시합니다.

    3. 본초와 방제¶

    • 본초학
    • 방제학
    • 임상 핵심 처방 100선: 출전·구성·용량
    • 본초 비교·감별 · 처방 구조·비교
    • 대표 본초 근거 카드
    • 한약 처방 임상근거

    본초와 방제는 효능·치법·임상영역별 분류와 질환별 근거를 연결합니다. 약재에서 처방으로, 증상에서 변증·처방으로 찾아가는 상세 경로는 본초·방제 지식축에서 확인할 수 있습니다.

    4. 경혈·침구치료¶

    • 침구·치료 통합 허브
    • WHO 표준 361경혈 임상 아틀라스
    • 침 치료 근거 카드

    경혈은 한글명과 WHO 국제 표준 코드를 함께 사용해 국내 검색과 국제 논문 탐색을 동시에 지원합니다. 경혈·침법 통합 탐색에서 경혈명·증상·근육·신경을 검색하고 경락·부위로 좁혀 표준경혈·사암침·동씨기혈의 기존 상세 문서로 이동합니다. 부위별 비교 학습과 3D 경혈 지도는 위치 이해를 돕고, 상세 본문은 위치·주치 출처·해부학·임상근거를 구분해 제공합니다.

    5. 지식그래프¶

    통합 한의학 지식 그래프에서는 본초·방제·증상·고전·연구 사이를 오가며 읽을 수 있습니다. 각 분야의 세부 관계는 다음 세 지식축으로 연결합니다.

    지식축 중심 관계
    본초·방제 증상·변증·치법, 구성 본초·배합, 처방 비교와 근거
    침구·신경·초음파 증상 위치·신경·근육, 경혈·침구와 임상해부학
    사상의학 소증·현재 병증, 체질병증·처방과 원전

    본초·방제 지식축¶

    본초·방제 영역은 증상과 변증에서 처방을 찾아가는 경로와 약재의 구성·배합에서 처방을 비교하는 경로를 함께 제공합니다. 보기·보혈·이기·화담·청열·이수 등 본초의 효능별 분류를 처방의 전체 치법과 연결하고, 고전의 수록 맥락과 현대 임상근거까지 이어 읽도록 구성합니다.

    핵심 허브¶

    찾는 내용 연결할 자료
    본초·방제의 전체 흐름 본초·방제 한눈에 보기
    효능별 약재와 임상영역별 처방 본초 찾기·방제 찾기
    약재의 역할과 처방 전체의 배합 본초→방제 역탐색·방제 구조
    증상·변증에서 처방 비교 방제→질환·변증 지도·질환→치료 지도
    고전·의가와 처방의 관계 의가·고전·처방 계보
    본초와 복합 처방의 현대 연구 본초 근거·한약·처방 임상근거

    • 피로할 때 보중익기탕과 십전대보탕은 무엇이 다른가요?

    페이지별 본문과 지식 그래프를 구분해 사용합니다¶

    page-index.json은 각 페이지의 제목·대표 HTML 주소(url)·JSON 주소(document)를 제공합니다. 한 주제의 본문을 읽을 때는 해당 document를 선택하거나 HTML의 JSON 대체 링크를 사용합니다. 페이지별 JSON에는 렌더링한 본문, 실제 제목 앵커, 출처·관련 링크가 담깁니다.

    본문 절에서 근거까지 확인하기¶

    페이지별 JSON의 sections는 실제 앵커가 있는 H2·H3 제목 단위의 제목·앵커 주소·해당 절의 본문·링크를 제공합니다. 다음 H2·H3가 나오기 전까지의 연속된 본문이 한 절에 담기며, H3 하위 절을 H2 본문에 다시 복사하지 않습니다. 첫 소제목 앞의 도입부나 앵커가 없는 HTML 제목의 내용은 전체 text에서 읽습니다. 이는 같은 공개 HTML을 다른 형식으로 제공하는 기능이며, 검색 노출을 위한 별도 요약문이나 새 의학적 판단을 생성하지 않습니다.

    단계 확인할 내용
    대표 문서 선택 색인의 제목과 url이 질문에 해당하는지 확인
    해당 절 읽기 sections의 제목·본문에서 답과 적용 조건을 함께 확인
    앞뒤 문맥 비교 전체 text와 HTML에서 정의·감별·안전 정보 확인
    출전 확인 절 안의 링크를 열어 원전 위치 또는 실제 연구 대상·중재·결과 확인
    인용 해당 절의 HTML 앵커 주소와 필요한 원출처를 함께 제시

    절의 links는 그 위치에 나타나는 링크 목록입니다. 참고문헌·내부 탐색 링크가 함께 들어갈 수 있으므로, 링크의 존재를 그 절의 모든 주장이 검증되었다는 뜻으로 해석하지 않습니다. 본문의 문헌명·판본·조문, 원방·가감방, 연구 제제와 적용 범위는 인용 과정에서도 유지합니다. 자료 차이의 처리 · 문서 상태 해석

    필드가 없거나 답이 충분하지 않을 때¶

    읽다가 만난 상황 다음 확인
    제목은 비슷하지만 다른 병증·처방을 설명함 문서 첫 문단과 출전을 비교해 질문에 맞는 대표 문서를 다시 선택
    절에 원출처 링크가 없음 전체 본문의 참고문헌 절과 관련 근거 카드를 확인하고, 원출처 확인 여부를 밝혀 설명
    JSON에 원하는 소제목이 없음 HTML의 실제 제목·표·도구 안내를 확인하고 전체 text와 비교
    날짜·검토자·식별자가 없음 작성일·감수자·PMID·DOI를 추정해서 채우지 않고 확인 가능한 범위만 사용
    HTML과 저장해 둔 JSON의 내용이 다름 현재 대표 HTML과 그 페이지가 연결한 JSON을 다시 확인하고 이전 수집본과 섞지 않음
    검색해도 질문에 답할 자료가 없음 찾지 못한 범위를 명시하고, 인접 문서의 설명을 해당 질문의 확정 답으로 바꾸지 않음

    제목·본문의 일치 여부는 검색 결과의 순서보다 먼저 확인합니다. 출처 확인 범위와 결과 수치 해석을 함께 적용하면 요약 과정에서 근거의 범위를 유지할 수 있습니다. 페이지별 JSON은 공개 본문의 읽기 자료이며, 검색 질의를 실행하는 API나 진단·처방을 반환하는 서비스로 제공하는 것은 아닙니다.

    지식 그래프는 문서 개체·동의어·분류·내부 연결을 탐색하는 자료이고, 매니페스트는 해당 빌드의 문서·관계 수와 무결성을 확인하는 자료입니다. 개별 주장을 인용할 때는 JSON 주소보다 원문 HTML의 해당 절과 연구 출처를 표시합니다. 데이터별 안내 · llms.txt

    문서 주소와 출처¶

    • 문서의 대표 주소와 제목 링크로 내용을 공유할 수 있습니다.
    • 질환 페이지는 환자 증상·감별·변증·치료·경과와 통합된 임상근거를 설명합니다.
    • 통합 전 주소로 들어왔으면 최종 도착한 대표 문서의 제목·해당 절을 확인해 인용합니다.
    • 고유한 근거 페이지와 근거 허브에서는 연구 요약·대상·치료 조건·원출처를 확인합니다.
    • 고전·민성의담은 서명·편목·판본 또는 날짜가 확인되는 기록을, 하루 카드는 해당 날짜·카드의 공유 링크와 연결 출처를 함께 확인합니다.

    • 전통적 활용과 현대 임상근거를 구분합니다.
