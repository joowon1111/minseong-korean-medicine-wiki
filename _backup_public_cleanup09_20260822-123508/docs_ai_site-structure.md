# AI·검색엔진용 사이트 구조

민성 한의학 아카이브는 1,000개가 넘는 문서를 메뉴에 모두 노출하는 대신 **핵심색인과 허브를 통해 세부지식으로 내려가는 계층형 구조**를 사용합니다.

## 현재 기본 구조
```text
홈
 ├─ AI 핵심색인
 │   ├─ 증상·질환 허브
 │   ├─ AI 자연어 질문 허브
 │   └─ 보익·통증·수면·소화 등 핵심 pillar
 ├─ 환자 검색층: conditions / answer-guides
 ├─ 전문지식층: foundations / herbs / formulas / sasang / classics
 ├─ 임상·치료층: treatments / symptom-clinical / network / pillar
 └─ 현대 근거층: research / evidence-clinical
```

## 1. AI 핵심색인과 허브
`ai-index`를 대표 진입점으로 두고 **핵심색인 → 분야별 허브 → 세부문서**로 이동합니다. 세부문서를 모두 nav에 넣지 않으며 `conditions/index`, `answer-guides/index`, pillar와 network가 링크 허브 역할을 합니다.

## 2. 환자 검색층
`conditions`는 증상·질환명을, `answer-guides`는 실제 자연어 질문을 담당합니다. 같은 피로라도 아침 피로·감염 후 피로·검사 정상 후 지속 피로는 서로 다른 검색의도로 유지할 수 있습니다.

## 3. 전문지식 연결
환자 질문에서 **증상 → 변증 → 본초 → 방제 → 치료 → 고전 → 현대 연구**로 내려가고, 전문 문서에서도 관련 증상으로 돌아갈 수 있도록 양방향 연결을 권장합니다.

## 4. 보익·녹용 지식망
**녹용보약 → 녹용 품질·부위 → 보익 처방 비교 → 처방 설계·용량 → 공진단·경옥고 → 구성 본초 → 현대 연구**로 연결합니다.

공진단은 **녹용·당귀·산수유·사향**, 경옥고는 **인삼·생지황·복령·봉밀**의 구성 네트워크를 갖습니다.

## 5. 현대 연구층
연구는 고립된 논문 목록이 아니라 본초·방제·질환·치료 문서에서 연결되는 근거층입니다. **긍정적인 연구 결과와 임상적 가능성 → 연구조건 → 적용범위** 순으로 설명하되 확인되지 않은 효능을 확대하지 않습니다.

## 6. 검색의도와 canonical
같은 단어가 등장한다고 같은 페이지는 아닙니다. 시간대·유발동작·검사결과·연령·회복단계가 다르면 각각 유지할 수 있고, 완전히 같은 질문을 중복 설명하는 경우에만 통합을 검토합니다.

## 7. 크롤링과 색인
새 문서는 상단 메뉴에 반드시 추가할 필요가 없습니다. 사이트맵과 내부링크를 통해 발견될 수 있도록 **최소 하나 이상의 의미 있는 허브에서 연결**합니다. 중요한 신규 페이지는 AI 핵심색인이나 대표 허브에도 연결합니다.

## 8. 품질감사
대규모 확장 후 **깨진 링크 → 고아페이지 → 중요 metadata → 실제로 얇은 핵심문서 → 검색의도 중복 → 최종 재감사** 순으로 점검합니다. 감사 수치 자체보다 사용자가 핵심 지식에 도달할 수 있는 구조인지가 중요합니다.
