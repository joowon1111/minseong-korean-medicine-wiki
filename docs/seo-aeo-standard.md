# SEO·AEO·GEO 문서 표준

민성 한의학 아카이브는 검색 노출만을 위한 문서가 아니라 **사람에게 실제로 도움이 되고, 검색엔진과 AI가 주제·관계·출처를 정확하게 이해할 수 있는 문서**를 만듭니다.

`사람에게 유용한 내용 → 명확한 문서 구조 → 연결 가능한 지식 관계 → 확인 가능한 근거와 출처`

## 가장 중요한 원칙

1. **사람 우선:** 환자의 질문에 실제로 도움이 되는 내용을 먼저 제공합니다.
2. **정확성과 관련성:** 문서 주제와 직접 관련된 정보만 포함하고 사실·링크·출처를 확인합니다.
3. **한 문서, 한 중심 주제:** 같은 내용을 여러 주소에 반복하지 않고 대표 문서를 정합니다.
4. **직접 답변:** 중요한 답을 서론 뒤에 숨기지 않고 첫 문단과 해당 질문 바로 아래에서 제시합니다.
5. **임상 맥락:** 증상명 하나를 특정 질환·변증·처방과 곧바로 동일시하지 않습니다.
6. **지식 연결:** 증상·질환·변증·치료·본초·방제·경혈·근거를 적절한 내부 링크로 연결합니다.
7. **출처 추적:** 현대 연구는 연구유형·대상·평가지표와 PMID·DOI를 가능한 범위에서 기록합니다.

Google 역시 검색 순위 조작을 위한 콘텐츠보다 사람에게 유용하고 신뢰할 수 있는 콘텐츠를 우선하도록 안내합니다.

## 문서 유형과 검색 의도

새 문서를 만들기 전에 사용자가 무엇을 알고 싶은지와 기존 대표 문서가 있는지를 먼저 확인합니다.

| 문서 유형 | 사용자의 주요 질문 | 권장 시작점 |
|---|---|---|
| 증상 | “이 증상이 무엇과 관련 있나요?” | 환자 표현·패턴·위험신호 |
| 질환 | “어떤 검사와 치료를 하나요?” | 정의·진단·감별·치료 |
| 본초 | “어떤 약재이며 어디에 활용하나요?” | 성미·귀경·효능·배합 |
| 방제 | “어떤 병기와 치법에 쓰나요?” | 출전·구성·치법·감별 |
| 침구·경혈 | “어디에 있고 어떻게 활용하나요?” | 위치·경락·해부학·주치 |
| 질문형 답변 | “내 상황에서는 무엇을 확인하나요?” | 한두 문장의 직접 답변 |
| 근거 | “사람 대상 연구에서 무엇이 평가됐나요?” | 연구유형·대상·결과·출처 |
| 허브·색인 | “관련 자료를 어디서 찾나요?” | 분류·비교·명확한 링크 |

기존 문서로 충분히 답할 수 있다면 새 문서를 만들기보다 기존 문서를 보강하고 관련 허브에서 연결합니다.

## 제목·설명·첫 문단

### 제목

- H1은 한 페이지에 하나만 사용합니다.
- 제목은 문서의 중심 주제 또는 실제 질문을 직접 표현합니다.
- 같은 키워드를 반복하거나 관련 없는 지역명·효과 표현을 억지로 붙이지 않습니다.
- 전문용어와 환자 검색어가 모두 중요하면 자연스럽게 함께 표기합니다.

좋은 예:

- `불면증·수면장애`
- `턱관절통증 — 입 벌릴 때 아프고 소리 나는 경우`
- `육미지황환(六味地黃丸)`
- `내관(內關) PC6`

### description

description은 문서가 무엇을 설명하며 어떤 핵심 내용을 찾을 수 있는지 한두 문장으로 요약합니다. 모든 페이지에 같은 홍보 문구를 반복하지 않습니다.

권장 구조:

> `[주제]의 핵심 특징, 확인할 점과 한의학적 치료자료·현대 임상근거를 정리합니다.`

검색결과의 실제 설명문은 검색엔진이 본문을 이용해 다르게 만들 수 있으므로 description은 정확하고 페이지별로 고유하게 작성합니다.

### 첫 문단

첫 문단에서는 다음을 바로 알려줍니다.

- 무엇을 다루는 문서인지
- 사용자가 찾는 증상·질환·약재가 맞는지
- 이 문서에서 무엇을 확인할 수 있는지

긴 역사 설명이나 일반론을 먼저 나열한 뒤 핵심 답변을 제시하지 않습니다.

## 증상·질환 문서의 권장 흐름

환자용 임상 문서는 가능한 범위에서 다음 순서를 따릅니다.

1. 내가 찾는 증상이나 질환이 맞는지
2. 즉시 진료가 필요한 위험신호
3. 원인과 관련 질환·검사·감별
4. 한의학적 해석과 변증
5. 한약·침·전침·약침 등 치료 선택과 조합
6. 관련 본초·방제·경혈·사상의학
7. 현대 임상연구와 주요 평가지표
8. 생활관리·회복 확인점
9. 관련 증상·질환·치료 문서

→ [아카이브의 임상 탐색 원칙](guide/index.md#clinical-navigation-principles)

## 질문형 답변과 AEO

질문은 환자가 실제로 묻는 표현으로 작성하고 답변 첫 문장에서 직접 답합니다.

좋은 질문:

- `입맛이 없을 때 한의학적 치료가 도움이 되나요?`
- `잠들기는 하는데 자꾸 깨는 이유는 무엇인가요?`
- `수술 후 기력과 식욕 회복을 어떻게 관리하나요?`

답변은 질문을 반복하거나 “전문가에게 문의하세요”로 끝내지 않고 다음 내용을 짧게 연결합니다.

`핵심 답변 → 어떤 경우에 해당하는지 → 위험신호·감별 → 치료자료 → 자세한 문서`

FAQ의 수를 늘리기 위해 내부 분류법이나 문서 제작 과정을 질문으로 만들지 않습니다. 같은 답변을 여러 문서에 복사하기보다 대표 답변으로 연결합니다.

## 내부 링크와 지식망

내부 링크는 검색엔진의 발견뿐 아니라 독자가 다음 판단으로 이동하도록 돕습니다.

- 링크 문구만 읽어도 이동할 내용을 알 수 있게 작성
- `여기`, `자세히 보기`만 반복하지 않고 구체적인 문서명 사용
- 코드처럼 보이는 경로나 원시 `.md` 주소를 본문에 그대로 노출하지 않음
- 대표 허브와 상세 문서를 양방향으로 연결
- 삭제·이동된 문서는 새 대표 문서로 연결
- 페이지 경로뿐 아니라 문단 앵커도 실제 존재하는지 확인

권장 관계:

`증상 ↔ 질환·감별 ↔ 변증·치법 ↔ 본초·방제 ↔ 경혈·치료 ↔ 현대 근거·출처`

세부 문서를 모두 좌측 메뉴에 나열하기보다 [AI 핵심 색인](ai-index.md), [전체 둘러보기](portal/maps.md)와 주제별 허브를 통해 접근하도록 구성합니다.

## 현대 연구와 출처

연구를 소개할 때 문서 주제와 직접 관련된 사람 대상 연구를 우선합니다.

- 연구유형: RCT·관찰연구·체계적 문헌고찰·메타분석 등
- 연구 대상과 주요 선정 기준
- 비교군과 치료 기간
- 주요 결과와 평가지표
- PMID·DOI 또는 공식 원문 주소
- 임상에서 해석할 때 필요한 맥락

논문 제목이나 초록을 길게 복사하지 않고, 무엇이 평가되었으며 결과가 임상적으로 어떤 의미인지 설명합니다.

→ [연구·근거](evidence-integrated/index.md) · [참고문헌 데이터베이스](research/references/index.md)

## 의료 콘텐츠 표현

- 한의학적 치료의 활용과 긍정적인 연구 결과를 충분히 설명합니다.
- 효과를 모든 사람에게 동일하게 보장하거나 질환의 완치를 단정하지 않습니다.
- 개인의 병기·동반질환·복용약·검사 결과에 따라 치료 구성이 달라질 수 있음을 자연스럽게 설명합니다.
- 응급상황과 중요한 위험신호는 치료 안내보다 앞에 배치합니다.
- 한약·침·전침·약침을 고정된 우열이나 순서로 제시하지 않고 치료 목적과 환자 상태에 따른 선택·조합으로 설명합니다.

## AI·GEO 친화적 구조

AI가 문서를 정확하게 이해하고 인용하려면 다음 요소가 중요합니다.

- 의미가 분명한 H1·H2·H3
- 질문 바로 아래의 직접 답변
- 한 문단에 하나의 중심 주장
- 비교가 필요한 내용은 표, 순서는 번호 목록
- 전문용어와 일상 표현의 명시적인 연결
- 주장과 가까운 위치의 출처
- 문서 작성일·검토일과 운영 주체
- 중복되지 않는 대표 문서와 안정적인 URL

AI로 초안을 만들거나 대량 보강한 경우에도 정확성·관련성·링크·출처를 사람이 검토합니다. 자동 생성 자체보다 최종 콘텐츠의 유용성·정확성·품질을 기준으로 판단합니다.

## 구조화 데이터와 기술 기준

- 구조화 데이터는 페이지에서 사용자가 실제로 볼 수 있는 내용과 일치해야 합니다.
- 존재하지 않는 저자·평점·질문·답변을 마크업에 추가하지 않습니다.
- 구조화 데이터는 검색 노출이나 순위를 보장하지 않습니다.
- 중복 페이지를 만들지 않고 하나의 대표 URL을 유지합니다.
- 내부 링크는 크롤러가 따라갈 수 있는 일반 링크로 제공합니다.
- 새 문서와 변경 문서는 사이트맵·검색 색인에 반영되는지 확인합니다.

Google이 지원하는 구조화 데이터 유형과 필수 속성을 확인한 뒤 적용하고 Rich Results Test로 검증합니다.

## 배포 전 점검표

- [ ] 제목과 H1이 문서의 실제 중심 주제를 나타내는가?
- [ ] description이 페이지마다 고유하고 정확한가?
- [ ] 첫 문단이나 질문 아래에 직접 답변이 있는가?
- [ ] 환자 표현과 전문용어가 자연스럽게 연결되는가?
- [ ] 위험신호·감별·치료·근거의 순서가 적절한가?
- [ ] 내부 링크와 문단 앵커가 모두 정상 작동하는가?
- [ ] 새 문서가 관련 허브·색인에 연결되어 있는가?
- [ ] 같은 주제의 중복 페이지가 없는가?
- [ ] 연구의 대상·설계·결과·PMID·DOI를 확인했는가?
- [ ] 구조화 데이터가 보이는 본문과 일치하는가?
- [ ] MkDocs 전체 빌드와 공개 페이지를 확인했는가?
