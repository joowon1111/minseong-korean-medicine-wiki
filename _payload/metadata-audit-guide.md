# 문서 메타데이터·품질 점검표

새 문서를 추가하거나 기존 문서를 크게 수정할 때 사용하는 최신 점검표입니다.

## 우선 확인
- `title`이 하나의 명확한 주제 또는 검색의도를 나타내는가?
- `description`이 문서 내용을 한 문장으로 직접 설명하는가?
- `tags`가 핵심 분류를 과도하지 않게 담는가?
- H1과 title이 의미상 일치하는가?
- 첫 화면에서 주제 또는 핵심 답변을 바로 알 수 있는가?
- 관련 허브에서 이 문서로 들어오는 내부링크가 있는가?
- 본초·방제·질환·치료·고전·연구로 다시 이동할 수 있는가?

## 권장 front matter
```yaml
---
title: 문서 제목
description: 문서의 핵심 범위를 한 문장으로 설명합니다.
tags: [핵심태그1, 핵심태그2, 핵심태그3]
status: 검토완료
last_reviewed: 2026-08-22
---
```

모든 과거 문서의 metadata 숫자를 기계적으로 100% 채우기보다 **환자 검색 가치가 높은 conditions·formulas·herbs·answer-guides와 핵심 허브를 우선**합니다.

## 분야별 기준
- 증상·질환: 주요 증상 + 감별 + 한의학적 해석 + 치료 접근
- 방제: 출전 + 구성 + 방의 + 전통적 활용 + 현대 연구
- 본초: 기원 + 성미·귀경 + 효능 + 처방에서의 역할 + 현대 연구
- 자연어 질문: 핵심 답변 + 구분해야 할 상황 + 치료·연구 연결

## 현대 연구
가능하면 연구유형·대상·치료방법·주요 결과·PMID/DOI를 기록합니다. 표현은 **현재 확인된 긍정적 신호 → 연구조건 → 임상적 의미 → 근거의 범위** 순서를 우선합니다.

## 내부링크
세부문서를 nav에 모두 등록하지 않고 **AI 핵심색인 → 주제 허브 → 세부문서** 경로를 확보합니다. 특히 `conditions/index`와 `answer-guides/index`는 대규모 세부문서를 연결하는 핵심 허브입니다.

## 중복 문서
같은 단어가 반복된다고 바로 중복으로 판단하지 않습니다. 아침 피로·감염 후 피로·검사는 정상인데 지속되는 피로처럼 검색의도가 다르면 `이 질문이 다루는 범위`와 `비슷하지만 다른 질문`으로 차별화합니다.

## 보약·본초·방제 추가 점검
- 출전과 원방 구조가 있는가?
- 절대 용량뿐 아니라 상대 구성비를 설명하는가?
- 원료 품질과 가공·제형을 구분하는가?
- 녹용·공진단·경옥고 구성 본초가 상호링크되는가?
- 현대 연구가 지나치게 부정적인 결론으로만 끝나지 않는가?
